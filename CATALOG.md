# Каталог Future Now

Бот і сайт читають таблицю `events`. За однакового `DATABASE_URL` це один каталог. Локальні `education.db` бота та `website.db` сайту залишаються окремими, доки обидва процеси не налаштовані на спільне сховище.

## Джерела та актуальність

- [МАН України](https://man.gov.ua/): оголошення освітніх можливостей. Новини з явними підсумками, нагородженням переможців або завершенням події позначаються завершеними.
- [Prometheus](https://prometheus.org.ua/courses-catalog/): сторінки курсів та офіційний публічний API каталогу. Постійно доступні курси позначаються «У власному темпі»; стара дата запуску не закриває їх.
- [Дія.Освіта](https://osvita.diia.gov.ua/courses): окремі сторінки освітніх серіалів.

Кожне оновлення повторно завантажує сторінки вибраних записів. Зберігаються час перевірки запису та стан кожного джерела. Це перевірка доступних даних першоджерела, а не гарантія прийому заявки організатором. Невказані ціна, вікові межі й дедлайни залишаються невідомими. Дата публікації та дата без року не перетворюються на дедлайн. Явний дедлайн завершує навіть курс для самостійного проходження.

У пошуку немає записів із простроченим дедлайном або ознакою завершення. В обраному вони залишаються зі статусом завершення. Повторний імпорт того самого URL оновлює запис, зберігаючи його ID та обране; рекламні параметри URL і фрагменти не створюють дублікати. Змістовні параметри посилання зберігаються.

Недоступність одного джерела не стирає каталог і не зупиняє імпорт інших джерел. Остання успішна перевірка зберігається. Сайт показує дату оновлення, стан джерел і попередження при збої або перевірці понад 48 годин тому. «Оновити результати» перечитує базу, а не запускає завантаження всіх сторонніх сайтів у запиті користувача.

## Оновлення

Єдиний власник регулярного оновлення спільної бази — процес бота. У звичайному серверному режимі `AUTO_REFRESH_ENABLED=true` запускає перевірку на старті й потім кожні `REFRESH_INTERVAL_SECONDS=21600` секунд (6 годин). Для serverless є захищений `/api/cron/refresh` та наявний workflow `bot-maintenance.yml` із розкладом раз на 6 годин. Його робота залежить від публікації актуального коду й налаштування секретів у GitHub/Vercel; самі зміни локального коду не активують хмарний розклад. На сайті другий планувальник не запускається.

Налаштування в `.env` backend:

```dotenv
CATALOG_SOURCES=man,prometheus,diia
CATALOG_SOURCE_LIMIT=12
```

Ліміт — кількість кандидатів на одне джерело за запуск, від 1 до 40. Це обмежена вибірка, а не повний каталог платформи. Відсутність запису в такій вибірці не закриває його автоматично. Мережеві запити мають таймаути; кількість паралельних запитів обмежена.

Із папки потрібного проєкту можна перевірити завантаження без запису в БД і без запуску Telegram:

```powershell
.\.venv\Scripts\python.exe -B refresh_catalog.py --limit 12
```

Оновити тільки локальну SQLite (відмовиться працювати з PostgreSQL):

```powershell
.\.venv\Scripts\python.exe -B refresh_catalog.py --apply --local-only --limit 12
```

Скрипт використовує `DATABASE_URL` цього проєкту; перевірте ціль перед запуском. Для одного джерела додайте `--sources prometheus`. Без `--apply` запису немає. CLI повертає ненульовий код, якщо всі вибрані джерела недоступні.

## Схема та перевірка

Додані `events.is_self_paced`, `events.is_closed`, `events.verified_at` та таблиця `catalog_sources`. Міграція доповнює схему й зберігає існуючі записи. Перед майбутньою публікацією обох застосунків на спільну PostgreSQL потрібно один раз виконати `setup_database.py` сайту з цільовим `DATABASE_URL`. Cold start Vercel схему не змінює.

Сайт повертає стан каталогу в `/api/v1/bootstrap` та авторизованому `GET /api/v1/catalog/status`. Час перевірки передається в UTC із суфіксом `Z`. Внутрішні причини помилок і секрети в публічну відповідь не потрапляють.

Для перевірки пошуку в поточній локальній вибірці: «Курси → 16–18 → Україна → Київ → Онлайн → Безкоштовно», дата без обмежень. Онлайн-курс для всієї країни підходить і для вибраного міста; явні обмеження іншого міста зберігаються.

Тести бота `tests/test_catalog.py` перевіряють парсинг, дедлайни, збої, повторний імпорт та збереження обраного. Тести сайту `tests/test_catalog_api.py` перевіряють API джерел, курси у власному темпі та прострочені записи. Всі вони використовують ізольовані тестові бази.
