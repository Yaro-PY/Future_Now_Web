# Future Now — сайт і API можливостей

Це окремий сайт у `D:\PyGameProjects\User_Flow`: адаптивний фронтенд і FastAPI з власними залежностями та запуском. Telegram-бот залишається в `D:\PyGameProjects\User-flow-main\User-flow-main`. Сайт не імпортує інтерфейс бота або aiogram і не виконує Telegram-запити.

Готовий React-інтерфейс відкривається на **http://127.0.0.1:8002/**. Екран входу — темна фотографічна композиція; каталог і особистий кабінет — світлий інтерфейс із прозорою навігацією. На телефоні працює нижнє меню, фільтри в діалозі та картка оголошення у виїзній панелі. Перемикач української / англійської доступний у верхній панелі.

Фронтенд написаний на **React 19 + Vite 8** у папці `frontend`. JSX-компоненти, React Context, hooks і React portals керують екранами, формами, станом та діалогами. Vite збирає сайт у `static/react`; FastAPI віддає збірку з тієї самої адреси, що й API. Node.js потрібен для розробки та збірки, а готовий сайт працює з Python-сервера. Підтримані вхід/реєстрація, три кроки анкетування, пошук/фільтри/пагінація, обране, деталі й повідомлення про проблеми, пропозиції, профіль, сповіщення, пароль, модерація. Джерела фото: [CREDITS.md](CREDITS.md).

Для спільного входу, профілів, фільтрів та обраного в обох проєктах потрібно вказати **той самий `DATABASE_URL`**. У production це наявна БД Neon. Без налаштувань сайт використовує власну локальну `website.db` — вона не містить даних робочого бота.

Підключення однієї Neon PostgreSQL до двох Vercel-проєктів: [SHARED_DATABASE.md](SHARED_DATABASE.md).

Каталог: МАН, Prometheus і Дія.Освіта; дата перевірки, стан джерел і курси у власному темпі. Завантаження та регулярне оновлення: [CATALOG.md](CATALOG.md). Перший локальний імпорт виконано; нова порожня база заповнюється явно через `refresh_catalog.py --apply --local-only`.

Адмінка: редагування опублікованих оголошень, захист ручних правок при оновленні джерел, статуси й коментарі до скарг. Доступ і сценарії: [ADMINISTRATION.md](ADMINISTRATION.md).

## Сценарій сайту

1. У верхній частині — перемикач української / англійської. До входу `GET /api/v1/bootstrap?lang=uk` повертає локалізовані назви меню, варіанти фільтрів, опис і довідку.
2. Вхід за **ніком та паролем** або реєстрація за ніком, імʼям і паролем. Імʼя — це звертання до людини, нік — логін. Збіг імені сам по собі не надає доступу до профілю.
3. Існуючий користувач бота задає пароль у приватному чаті через `/password`. На сайті вводить цей самий нік і пароль та отримує той самий профіль, збережені фільтри, обране й пропозиції.
4. Новий користувач сайту бачить `onboarding_required: true`: фронтенд пропонує вік, географію та формат. Після `PUT /me/profile` із коректною віковою групою ознака стає `false`. `filters_setup_required: true` означає наступний крок — вибір фільтрів. Після їх збереження або першого пошуку ця ознака стає `false`. Заповнений профіль Telegram-бота одразу відкриває каталог з його збереженими вподобаннями, навіть якщо окремого пошуку ще не було. Старі формати віку нормалізуються у відповіді API без перезапису профілю.
5. Основне меню: пошук, обране, запропонувати можливість, мої пропозиції, профіль, налаштування, про сервіс. Профіль і перемикач мови можна розмістити у верхній панелі. Для адміністратора `user.role` дорівнює `admin`.
6. Картки пошуку містять теги, вартість, дати й стан оголошення. Обране зберігає й завершені записи. У профілі редагуються імʼя, нік та вподобання; у налаштуваннях — мова, сповіщення й пароль.

## Пароль і спільні дані

- Пароль: 12–128 символів, без обрізання пробілів. Зберігається Argon2id-хеш, а не початковий текст.
- У боті пароль вводиться двічі. Повідомлення з ним видаляються за можливості; бот не повторює пароль у відповідях. Скасування видаляє чернетку налаштування пароля.
- Старий профіль без пароля можна захистити тільки з його Telegram-акаунта. Реєстрація на сайті із зайнятим ніком не привласнює профіль.
- Якщо спочатку зареєструватися на сайті, у боті є `/login`: нік → пароль. Перший вхід привʼязує сайт до цього Telegram, зберігаючи постійний ID, профіль, фільтри, обране, пропозиції й чинну сесію сайту. До іншого Telegram цей логін повторно не привʼязується.
- Нове імʼя не змінює пароль. Зміна ніка оновлює логін одночасно в боті й на сайті.
- Останні застосовані фільтри пошуку спільні. Пошук у боті, пошук на сайті й `PUT /me/filters` зберігають їх у `accounts.search_defaults`.
- `/password` у боті та зміна пароля на сайті завершують усі браузерні сесії цього профілю. Відновлення через email поки не реалізоване; власник привʼязаного Telegram може задати новий пароль через `/password`.
- Сповіщення в Telegram надсилаються тільки після привʼязування Telegram та відповідно до налаштувань.

## Локальний запуск сайту

Потрібні Python і Node.js 22.12+ (або сумісна версія з `frontend/package.json`). Для першого запуску або після зміни React-коду:

```powershell
npm ci --prefix frontend
npm run build --prefix frontend
```

З цієї папки, PowerShell:

```powershell
.\START_WEBSITE.bat
```

У цій робочій копії окреме середовище сайту вже підготовлене. Для нової копії створіть його:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\START_WEBSITE.bat
```

Або запустіть вручну:

```powershell
$env:DATABASE_URL = 'sqlite+aiosqlite:///./website.db'
$env:PORT = '8002'
.\.venv\Scripts\python.exe -B main.py
```

Сервер сайту працює окремо від бота. Дані підключення можна задати у власному `.env`, створеному за `.env.example`. Реальні `.env`, токени, робочі бази та Git-історія з папки бота сюди не копіювалися.

- Swagger: `http://127.0.0.1:8002/docs`
- Сайт: `http://127.0.0.1:8002/`
- OpenAPI: `http://127.0.0.1:8002/openapi.json`
- Стан: `http://127.0.0.1:8002/health`
- Адреси API починаються з `/api/v1`.

Порожня локальна база не містить оголошень: інтерфейс показує порожній каталог, а не вигадані можливості. Для розробки можна імпортувати власний JSON через `import_events.py` з тим самим `DATABASE_URL`; `examples/opportunities.json` демонструє формат і не гарантує актуальних дат. Самі фільтри й пароль не копіюються між локальними файлами БД автоматично: обидва застосунки мають підключатися до одного сховища.

## Сесія, CSRF і CORS

Після входу або реєстрації сервер встановлює дві HttpOnly-cookie та повертає `user` і `csrf_token`. Тривалість сесії — 7 днів, налаштовується `WEB_SESSION_DAYS` (1–30). В БД зберігаються лише хеші сесійних секретів. Пароль і cookie не треба записувати в localStorage.

Фронтенд виконує `fetch(..., {credentials: 'include'})`. Для запитів, що змінюють дані, додає заголовок `X-CSRF-Token`, отриманий після входу. Після перезавантаження сторінки `GET /auth/session` відновлює користувача та CSRF-токен. Вхід і реєстрація не потребують попередньої сесії. Вихід потребує CSRF та відкликає сесію на сервері.

`WEB_ALLOWED_ORIGINS` — перелік точних адрес фронтенду через кому, без шляхів і `*`. Локально за замовчуванням дозволено `http://localhost:5173,http://127.0.0.1:5173`; на Vercel список за замовчуванням порожній. Запити з власного origin backend дозволені. Для CORS-клієнта задайте його адресу явно.

HTTPS/Vercel автоматично використовує Secure-cookie. Для frontend та API на різних сайтах потрібні `WEB_COOKIE_SAMESITE=none` і `WEB_COOKIE_SECURE=true`, а браузер має дозволяти відповідні cookie. Рекомендований спосіб розгортання — один origin або проксі `/api` на домені фронтенду.

Помилки мають вигляд `{"error":{"code":"invalid_credentials","message":"..."}}`. Неправильні поля — HTTP 422 із масивом `error.fields`, без повернення введених значень. Немає сесії — 401, немає дозволу/CSRF — 403, конфлікт — 409, перевищено ліміт спроб — 429. Приватні відповіді мають `Cache-Control: no-store`.

## Основні маршрути

- `GET /bootstrap?lang=uk|en` — назва Future Now, мови, меню, довідка, варіанти фільтрів і стан входу.
- `POST /auth/register` — `nickname`, `display_name`, `password`, `language`; створює акаунт і сесію.
- `POST /auth/login` — `nickname`, `password`; повертає спільний профіль бота/сайту.
- `GET /auth/session`, `POST /auth/logout`, `POST /auth/password` — керування сесією й паролем. Зміна пароля приймає `current_password`, `new_password` та вимагає нового входу.
- `GET /me`, `PUT /me/profile` — читання та редагування профілю. Для збереження потрібні `nickname`, `display_name`, `age`; також приймаються `country`, `city`, `format`, `criteria`.
- `GET /me/filters`, `PUT /me/filters` — спільні фільтри: `type`, `age`, `country`, `city`, `format`, `date`, `criteria`.
- `PATCH /me/settings` — `language` та/або `notifications: {new, deadlines, expired}`. Обʼєкт сповіщень замінюється цілком; значення за замовчуванням: false, false, true.
- `POST /opportunities/search` — `filters` (необовʼязково), `query`, `page`, `page_size`; повертає `items`, `total`, `pages` і застосовані фільтри. Без `filters` використовує збережені. Потребує сесії й CSRF, оскільки запамʼятовує вибір.
- `GET /opportunities/{id}` — докладна картка з тегами та станом обраного/підписки.
- `GET /opportunities/{id}/registration` — перевіряє доступність посилання перед переходом.
- `GET /me/favorites`, `PUT /me/favorites/{id}`, `DELETE /me/favorites/{id}` — обране; повторні додавання й видалення безпечні.
- `PUT /me/subscriptions/{id}` — `{enabled: true|false}`, стан підписки та доступність Telegram-доставки.
- `POST /me/proposals`, `GET /me/proposals` — надсилання й перегляд власних пропозицій. Поля оголошення описані в OpenAPI. Модерація, перевірка повторів і ліміти спільні з ботом.
- `POST /me/reports` — `event_id` (необовʼязково), `category`, `message`.
- `GET /admin/proposals`, `PATCH /admin/proposals/{id}`, `POST /admin/proposals/{id}/decision`, `GET /admin/reports` — тільки для власника `ADMIN_ID`, який увійшов своїм паролем. Рішення: `decision: approved|rejected`, `reason`; для відхилення причина обовʼязкова.

Пагінація починається з 1; типовий розмір сторінки — 10, максимальний — 50. Дати участі обробляються за Europe/Kyiv. Прострочені оголошення не потрапляють у пошук. Невідомі вік, формат або вартість не задовольняють відповідний конкретний фільтр. Тематика — теги картки. Текст із JSON фронтенд показує через textContent/звичайні текстові компоненти, без вставки в innerHTML.

## Розробка React і підключення іншого клієнта

- `frontend/src/App.jsx` — вхідна точка React; `app/AppProvider.jsx` — сесія й спільні дії, `app/AppShell.jsx` — оболонка та діалоги.
- `frontend/src/routing/` — централізовані маршрути, групи розділів і відкладене завантаження екранів.
- `frontend/src/hooks/` — запити з ігноруванням застарілих відповідей, пошук після паузи, локалізація й повідомлення.
- `frontend/src/pages/` — вхід, каталог, напрями, профіль, налаштування, пропозиції, модерація та центр допомоги.
- `frontend/src/components/` — форми, навігація, SVG-іконки, модальні діалоги та панель оголошення.
- `frontend/src/context.jsx` — React Context і спільні функції; `i18n.js` — українські/англійські тексти.
- `frontend/src/api.js` — клієнт із HttpOnly-cookie, CSRF та обробкою помилок. Паролі та сесійні токени не записуються в localStorage.
- `frontend/src/styles.css` — візуальна система; `sections.css` — напрями й допомога; `responsive.css` — адаптація сіток, форм і навігації.
- `static/react/` — готова збірка; `static/images/` — фото. Збірка очищає тільки власну папку `static/react`.

Повна структура описана у [frontend/README.md](frontend/README.md). До 480 px каталог має одну колонку, від 480 до 1439 px — дві, від 1440 px — три. До 1024 px фільтри відкриваються в діалозі. До 768 px працює нижня навігація. На сенсорних екранах збільшені області натискання, поля від 16 px та враховані safe-area, горизонтальне положення й динамічна висота екрана.

Для редагування з автоматичним оновленням запустіть FastAPI на `8002`, а в другому терміналі:

```powershell
npm run dev --prefix frontend
```

Відкрийте **http://127.0.0.1:5173/**. Vite проксіює `/api` і фото на FastAPI `127.0.0.1:8002`; cookie й CSRF працюють через цей самий origin. Якщо backend використовує інший порт, змініть proxy у `frontend/vite.config.js`. Після завершення редагування знову виконайте `npm run build --prefix frontend`, щоб оновити сторінку на `8002`.

Ресурси розміщені локально; сторонні шрифти, аналітика або зображення не завантажуються під час роботи інтерфейсу. Фото в картках ілюструють категорії, а не конкретних організаторів. У production відображаються тільки записи підключеної БД. Демонстраційні записи для браузерних перевірок зберігаються в окремих тестових файлах `.qa` і не публікуються.

Готовий транспорт без інтерфейсу: [examples/website-client.js](examples/website-client.js).

```javascript
import { FutureNowAPI } from './website-client.js';
const api = new FutureNowAPI('/api/v1');
const initial = await api.bootstrap('uk');
const session = await api.login(nickname, password);
// onboarding_required визначає, чи показувати анкету;
// filters_setup_required — чи запропонувати налаштування фільтрів.
const results = await api.search({ filters: { type: 'course', age: 'any' } });
await api.saveFavorite(results.items[0].id);
await api.saveSettings({ language: 'en' });
```

Після перезавантаження викличте `api.resume()`. За 401 покажіть вхід; за 422 — помилки полів; за 429 — повідомлення про паузу. Перемикач мови до входу використовує `bootstrap(lang)`, після входу — `saveSettings({language})`.

## Публікація на Vercel + Neon

Публікуйте цю папку як **окремий Vercel-проєкт сайту**, з коренем у `User_Flow`. Бот розгортається зі своєї папки. `vercel.json` зберігає FastAPI й Frankfurt та перед розгортанням запускає `npm ci --prefix frontend --include=dev && npm run build --prefix frontend`. Параметр `--include=dev` встановлює Vite для збірки навіть із `NODE_ENV=production`. `frontend/package-lock.json` фіксує залежності. Поле Output Directory залишається стандартним для FastAPI. Код містить таблиці `credentials`, `web_sessions`, `auth_throttles`; вони спільні з ботом. Холодний старт Vercel не виконує міграції, а preview не обслуговує робочу БД.

1. Опублікуйте код із новою залежністю `pwdlib[argon2]`.
2. У Production задайте той самий `DATABASE_URL`, що й у бота, та `ADMIN_ID`. Додайте точний `WEB_ALLOWED_ORIGINS`, коли буде домен фронтенду. Для одного origin додатковий CORS-домен не потрібен. `BOT_TOKEN`, `WEBHOOK_SECRET` і `CRON_SECRET` сайту не потрібні.
3. Якщо схема ще не створена, задайте потрібний `DATABASE_URL` у середовищі/локальному `.env` та один раз виконайте:

```powershell
.\.venv\Scripts\python.exe -B setup_database.py
```

Скрипт створює відсутні таблиці додатково й зберігає наявні записи. Він не змінює Telegram webhook. Не передавайте рядок підключення в URL або командному рядку; зберігайте його як секрет середовища.

4. У боті `/start` або `/password` → пароль двічі. Увійдіть на сайт тим самим ніком і паролем; перевірте спільний профіль, фільтри й обране.

У межах розробки цієї зміни робочі таблиці Neon не мігрувалися та новий код не публікувався автоматично.

## Спільний контракт із ботом

`database.py`, `web_auth.py`, `identity.py`, `account_preferences.py`, довідники та перевірки оголошень використовують сумісний контракт обох проєктів. При зміні схеми або правил пароля оновлюйте обидві копії. Telegram UI та парсер МАН залишаються в папці бота. API, його схеми, приклад фронтенд-клієнта й тести окремого HTTP-сервера — у цій папці.

## Перевірки

```powershell
.\.venv\Scripts\python.exe -B -m unittest -v
```

Перед перевірками зберіть React командою `npm run build --prefix frontend`. Тести сайту використовують окремі бази й не потребують aiogram. Перевіряються вхід, фільтри/обране, пароль, сесії, CSRF, ліміти входу, пропозиції, віддавання React-збірки та перезапуск HTTP-сервера. У папці бота є окремі інтеграційні перевірки спільного входу, двосторонніх фільтрів та модерації з імітацією Telegram.

Механізми хешування й cookie звірені з офіційною документацією [FastAPI](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/), [CORS](https://fastapi.tiangolo.com/tutorial/cors/) та [Starlette](https://starlette.dev/responses/).


## Пропозиції та доступ до акаунта

Редагування та відкликання власних пропозицій до перевірки, відновлення доступу через Telegram і видалення спільного профілю описано в [USER_CONTROLS.md](USER_CONTROLS.md). Перед оновленням Vercel виконайте [міграцію 002](migrations/002_user_controls.sql) один раз у спільній Neon.
