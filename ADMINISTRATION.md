# Адміністрування Future Now

У меню профілю адміністратора відкрийте **«Модерація»**. На сторінці є три вкладки: «Пропозиції», «Опубліковані» та «Скарги». Вона адаптована до телефона, планшета й компʼютера та перекладається українською й англійською.

## Доступ

Адміністратор — власник Telegram-акаунта з ID, заданим у backend-параметрі `ADMIN_ID`. На сайті він входить своїм звичайним ніком і паролем, попередньо заданим у боті через `/password`. Для спільного входу бот і сайт мають використовувати одну БД. Права не можна отримати через форму реєстрації або зміну профілю.

Задайте `ADMIN_ID` у власному `.env` сайту та перезапустіть його. Значення має відповідати ID саме адміністратора, а не ID бота. Пароль чи `BOT_TOKEN` у React не додаються. Сервер перевіряє права на кожен адміністративний запит; усі зміни також потребують чинної сесії та CSRF-токена.

## Опубліковані оголошення

- Пошук за назвою, фільтр доступних / завершених, пагінація та перегляд звичайної картки.
- Редагування назви, опису, публічного посилання, типу, тем, країни, міста, формату, віку, дат, оплати, організатора, мови й умов участі.
- Окремі перемикачі «У власному темпі» та «Позначити оголошення завершеним». Закриття прибирає оголошення з пошуку та подання заявки, але зберігає його в обраному зі статусом завершення. Повторне відкриття знімає явну ознаку завершення; прострочений дедлайн також потрібно виправити, якщо організатор продовжив прийом.
- Зміна посилання перевіряє публічну адресу, її доступність та дублікати в каталозі. Джерело походження запису не редагується.
- ID оголошення та обране зберігаються. Автоматичне оновлення джерел зберігає змінені адміністратором поля; незмінені поля продовжують оновлюватися. Повʼязані поля оплати, вікових меж та місця захищаються разом.

Форма завантажує актуальну версію перед редагуванням. Якщо запис змінено іншим запитом або оновленням джерела, сервер повертає `409 edit_conflict`. Незбережений текст залишається у формі; кнопка «Завантажити актуальну версію» замінює його свіжими даними. Це запобігає непомітній перезаписі нових правок.

## Скарги

Початковий фільтр «Необроблені» показує нові звернення й ті, що вже в роботі. Можна відкрити всі звернення або конкретний статус.

1. Відкрийте «Опрацювати»: видно категорію, текст, дату й повʼязане оголошення.
2. Позначте «У роботі» або перейдіть до перегляду / редагування оголошення.
3. Після перевірки оберіть «Вирішені» чи «Відхилені» та додайте коментар щонайменше з 5 символів. Рішення не видаляє звернення.
4. За потреби поверніть звернення у «Нові» або «У роботі». Час закриття очищається, початковий текст і дата створення залишаються.

Звернення щодо сервісу без оголошення теж можна опрацювати. Коментарі призначені для адміністратора. У браузер не передаються Telegram ID автора звернення, пароль чи сесійні секрети. Для одночасного опрацювання діє така сама перевірка версії, як для оголошень.

## API та зберігання

- `GET /api/v1/admin/opportunities?q=&state=all&page=1&page_size=10`
- `GET /api/v1/admin/opportunities/{id}`
- `PATCH /api/v1/admin/opportunities/{id}`: `{ "expected_revision": 1, "values": { ... } }`. `values` — повний набір редагованих даних із GET, включно з незмінним `source`.
- `GET /api/v1/admin/opportunities/{id}/history`: останні 50 ручних редагувань із попередніми та новими значеннями.
- `GET /api/v1/admin/reports?status=open&page=1&page_size=10`
- `PATCH /api/v1/admin/reports/{id}`: `{ "expected_revision": 1, "status": "resolved", "review_note": "Умови уточнено." }`.

Дозволені стани оголошень: `all`, `available`, `expired`. Статуси звернень: `new`, `in_progress`, `resolved`, `dismissed`; фільтри також приймають `open` та `all`.

Таблиця `admin_audit` зберігає автора, час та зміни ручних редагувань і рішень щодо звернень. У `events` додані версія, прапорці захищених полів, оригінальне посилання джерела та метадані ручного редагування. У `reports` додані версія, статус, коментар та час опрацювання. Моделі однакові у сайті й боті.

Локальний запуск доповнює схему без видалення записів. Перед майбутньою публікацією на наявну Neon виконайте `setup_database.py` сайту один раз із правильною backend-змінною `DATABASE_URL`, потім опублікуйте обидва проєкти. Холодний старт Vercel міграцій не запускає. Ця реалізація сама не змінює хмарну БД чи deployment.

## Перевірки

`tests/test_admin.py` використовує ізольовану SQLite й імітацію перевірки посилань. Покриті права й CSRF, конфлікти версій, валідація, дублікати, збереження обраного, ручних правок і ціни при імпорті, міграція старих звернень, рішення / повторне відкриття, фільтри й пагінація. Браузерні перевірки виконуються на окремій демонстраційній базі, а не на користувацьких записах.
