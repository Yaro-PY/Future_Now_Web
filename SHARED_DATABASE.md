# Одна база для Future Now: бот и сайт

Нужна одна существующая Neon PostgreSQL, подключённая к двум проектам Vercel. Бот находится в `User-flow-main/User-flow-main`, сайт — в `User_Flow`. Пользователи, пароли, фильтры, избранное, объявления и предложения хранятся в общих таблицах.

## Подключение в Vercel

1. Откройте существующую базу `user-flow-db` в Storage. Новую базу для сайта создавать не нужно.
2. В Connect Project / Projects подключите проект бота и отдельно проект сайта. Для обоих выберите Production.
3. Оба production-проекта должны использовать одну production-ветку Neon и одну базу внутри неё. Пункт Create database branch for deployment → Production оставьте выключенным.
4. В Environment Variables обоих проектов должна быть переменная `DATABASE_URL` с тем же pooled URL PostgreSQL. Обычно хост содержит `-pooler`, а строка содержит `sslmode=require`. Если интеграция создала переменную с другим префиксом, добавьте `DATABASE_URL` с тем же значением.
5. Выполните Redeploy обоих проектов: изменённые переменные применяются к новым deployment.

`DATABASE_URL` задаётся только backend-процессам. Его не нужно добавлять в React как `VITE_DATABASE_URL`, публиковать в репозитории или передавать в чат. `BOT_TOKEN` нужен проекту бота; сайту он не нужен.

Приложения Vercel уже требуют PostgreSQL в production. React обращается к API сайта, а API читает и меняет общую базу. При чтении результатов синхронизации кнопки интерфейса или страницу нужно обновить; мгновенные push-обновления вкладки пока не реализованы.

## Схема и существующие данные

Проверка совместимости моделей есть в `tests/test_api.py` сайта. Интеграционные проверки бота находятся в `tests/test_website_integration.py`: общий вход, двусторонние фильтры и избранное, привязка Telegram и защита от перезаписи свежих настроек старым экраном бота.

Существующие записи Neon сохраняются. Подключение к той же базе не переносит данные из локальных `education.db` и `website.db` автоматически. Если локальные записи нужны в production, их импорт выполняется отдельно с проверкой совпадений.

Перед публикацией версии с обновлённым каталогом используйте скрипт сайта `setup_database.py`: он добавляет таблицы авторизации, `catalog_sources` и поля `events.is_self_paced`, `events.is_closed`, `events.verified_at`, если их ещё нет. Перед запуском в `.env` сайта должен быть задан нужный PostgreSQL `DATABASE_URL`; без него скрипт использует локальную SQLite. Скрипт добавляет недостающую схему и не вызывает Telegram. Холодный старт Vercel схему не меняет. Секреты не передаются в аргументах команд.

## Проверка после подключения

1. `/health` бота и сайта должны вернуть `OK`.
2. В боте задайте пароль через `/password`, затем войдите на сайт тем же ником и паролем.
3. Измените фильтры на сайте, затем начните новый поиск в боте: должны примениться те же фильтры.
4. Сохраните объявление на сайте и откройте «Обране» в боте. Затем проверьте обратное направление.
5. Создайте предложение на сайте и проверьте, что администратор видит его в общей очереди модерации.

Для разделённых проектов один backend не вызывает второй для переноса данных: оба работают с одной базой. Обновление источников и Telegram-уведомления выполняются задачами проекта бота.
