# Фото профілю, пароль і двофакторна автентифікація

## Для користувача

На сайті «Профіль» → «Завантажити фото»: JPEG, PNG або WebP до 2 МБ, статичне зображення до 16 мегапікселів. Сервер вирівнює орієнтацію, обрізає до 512×512, прибирає метадані та зберігає WebP до 256 КБ. Фото видно у профілі й меню; його можна замінити або видалити. Воно приватне, доступне лише після входу. Фото зберігається у тій самій Neon, тому не залежить від тимчасових файлів Vercel. Прив’язка акаунта сайту до бота переносить фото, видалення профілю стирає його.

Новий мінімум пароля — 8 символів, максимум 128. Це діє для реєстрації, зміни й відновлення пароля на сайті та в боті. Попередні паролі залишаються чинними. Паролі зберігаються як Argon2id-хеші.

«Налаштування» → «Двофакторний захист» дозволяє увімкнути Google Authenticator або Telegram, або обидва способи. Спочатку треба підтвердити поточний пароль; якщо 2FA вже працює, також чинний другий фактор. Для Google Authenticator відскануйте локально сформований QR-код (або введіть ключ вручну) і підтвердьте шестизначним кодом. Сумісні інші застосунки TOTP. Для Telegram спочатку прив’яжіть профіль через /login у боті; далі відкрийте спеціальне посилання та введіть код із приватного чату. Код отримує тільки Telegram-власник відповідного профілю.

Після першого ввімкнення показуються 8 резервних кодів. Збережіть їх: кожен діє один раз, повторно переглянути їх не можна. Новий набір можна створити в налаштуваннях із підтвердженням пароля й другого фактора; він замінює попередній.

Під час наступного входу правильний пароль відкриває екран 2FA. Сесія створюється тільки після коду з будь-якого ввімкненого способу або резервного коду. Запит діє 5 хвилин, максимум 5 неправильних спроб. Telegram-код можна запросити повторно через хвилину; новий замінює попередній. TOTP діє 30 секунд з допуском одного сусіднього інтервалу. Повторне використання того самого TOTP заборонене: дочекайтеся нового коду. Вмикання й зміни 2FA завершують інші сесії, зберігаючи поточну підтверджену сесію.

Відновлення пароля через Telegram не вимикає 2FA. Для входу після відновлення все одно потрібен другий фактор або резервний код. Прив’язка нового Telegram через /login теж перевіряє TOTP або резервний код для захищеного акаунта сайту.

## Технічна реалізація

Спільні модулі: two_factor.py, web_auth.py, profile_media.py, database.py. API й контракти: security_api.py, web_api.py, web_schemas.py. React: Security.jsx, ProfilePhoto.jsx та існуючі сторінки входу/профілю. Нові таблиці: account_avatars (BYTEA), two_factor, auth_challenges; accounts.avatar_revision керує URL фото.

TOTP використовує PyOTP/RFC 6238. Активний і тимчасовий секрети зашифровані Fernet. Telegram-коди та резервні коди зберігаються лише як HMAC-SHA256 із серверним ключем. Запит другого фактора прив’язаний до HttpOnly cookie браузера; його токен зберігається в БД як SHA-256. Парольний знімок і ревізія налаштувань анулюють запит після зміни захисту. Лічильник TOTP та одноразові запити захищені перевіркою й атомарним оновленням, на PostgreSQL також блокуванням рядків. Жодного JWT або зовнішнього сервісу QR-кодів немає.

Вимкнення/зміни 2FA потребують одноразової авторизації поточним паролем і чинним фактором. Секретів немає у bootstrap, user, security status, localStorage чи журналах. Відсутній/неправильний ключ не дозволяє обійти захист. Код бота для Telegram не потребує BOT_TOKEN на сайті: після переходу користувача за посиланням код створює й надсилає сам бот.

API: GET/PUT/DELETE /api/v1/me/avatar; GET /api/v1/me/security; POST /api/v1/me/security/authorize; POST /api/v1/me/security/{totp|telegram}/setup, /enable, /disable; POST /api/v1/me/security/recovery-codes; POST /api/v1/auth/2fa/verify і /cancel. Мутації авторизованої сесії потребують CSRF і перевірки Origin. Файли передаються сирими байтами з image/jpeg, image/png або image/webp.

## Локальний запуск

Встановіть requirements.txt в обох віртуальних середовищах. З папки бота запустіть:

    python setup_security_key.py --website-dir D:/PyGameProjects/User_Flow

Команда один раз створює спільний AUTH_ENCRYPTION_KEY у локальних .env (значення не друкується), повторний запуск його зберігає. Якщо наявні ключі відрізняються, команда зупиниться без заміни. Не змінюйте ключ після підключення автентифікаторів: без старого ключа секрети неможливо розшифрувати. Після додавання ключа перезапустіть обидва локальні застосунки. init_db додає локальні таблиці й колонку без видалення записів.

## Vercel: порядок публікації

1. У наявній спільній Neon user-flow-db виконайте весь migrations/003_profile_security.sql із Read-only OFF. Це один повторюваний DO-блок; наявні користувачі/оголошення не стираються, для всіх 2FA початково вимкнено. Базові міграції 001 і 002 мають уже бути застосовані.
2. У Production обох Vercel-проєктів user-flow-bot та future-now-web додайте секрет AUTH_ENCRYPTION_KEY з однаковим значенням. Можна перенести готовий ключ із локального .env без публікації в чаті або GitHub. Не генеруйте окремі ключі для сайту й бота. Новий BOT_TOKEN на сайті не потрібний.
3. Опублікуйте обидва проєкти з новими requirements.txt. Холодні старти Vercel не запускають міграції. /health перевіряє нові таблиці й колонку. Якщо ключ ще не задано, звичайний вхід без 2FA працює, але налаштування 2FA недоступні; увімкнений захист завжди залишається обов’язковим.
4. Перевірте фото, увімкнення Authenticator, збереження резервних кодів, вихід і повторний вхід; окремо підключіть Telegram і повторіть вхід з його кодом.

Тести використовують окремі SQLite/PGlite й фальшивий Telegram. Розробка не змінює робочу Neon і не надсилає справжніх кодів користувачам.
